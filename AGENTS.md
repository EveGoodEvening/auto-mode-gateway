## Lessons

- Codex docs moved (as of 2026-10): every `https://developers.openai.com/codex/<path>` URL 308-redirects to `https://learn.chatgpt.com/docs/<path>`; append `.md` for clean text (e.g. `learn.chatgpt.com/docs/config-file/config-reference.md`). The `docs/*.md` files in `github.com/openai/codex` are one-line stubs now. Index: `https://learn.chatgpt.com/llms.txt`.
- For Codex internals, shallow-clone `openai/codex` into the scratchpad and grep; file paths guessed from older docs/blogs (`openai_tools.rs`, `model_provider_info.rs`, `chat_completions.rs`) no longer exist. Current locations: tool specs `codex-rs/core/src/tools/handlers/shell_spec.rs` + `apply_patch_spec.rs`; provider config `codex-rs/model-provider-info/src/lib.rs`; Responses SSE parser `codex-rs/codex-api/src/sse/responses.rs`; approval enums `codex-rs/protocol/src/protocol.rs` + `config_types.rs`; Auto-review `codex-rs/core/src/guardian/` + `codex-rs/prompts/templates/guardian/policy.md`.
- Codex (CLI 0.164.0, 2026-10-23) speaks only the Responses API: `wire_api = "chat"` was removed in rust-v0.95.0 (2026-02-04, PR #10498). The shell tool is `exec_command` (+ `write_stdin`), not `shell`/`shell_command`; `--ask-for-approval` accepts only `on-request` | `never`; `--full-auto` is deprecated/removed, `--approve-for-me` and `--yolo` exist.
- C01 bootstrap (2026-10-28, `agent://c01-bootstrap-1`) deliberately pinned TypeScript 5.9.3 and `eventsource-parser` 3.1.1 rather than moving latest majors; these remain the actual selected versions. Parser v3 uses `createParser({ onEvent })`, not the older callback-only form. Actual tsup is 8.5.0 after declaration repairs, not initial 9.0.0. Supported Node remains `^24.11.0 || >=26.0.0` (Node 24.11+, excludes Node 25); see `docs/plan/PROGRESS.md` for historical selections and evidence.
- C01 toolchain: tsup 9.0.0 and 8.5.1 publish declarations importing absent `./types.cts`; use 8.5.0 with exact `@swc/core` 1.16.20 type peer, without skipLibCheck. npm >=12 with engine-strict enforces the supported installer; versioned allowScripts permits esbuild 0.25.12/0.28.2 and denies SWC installer. Refresh approvals when lock changes.
- Register only implemented CLI commands via `register<Name>Command(program: Command): void`, and use `await program.parseAsync()` so asynchronous action failures reach the entrypoint. Preserve Commander-managed version/help behavior and derive the version from package metadata.
- Treat unexpected CLI errors as potentially secret-bearing: never print arbitrary exception messages, causes, stack traces or configuration. Emit a fixed diagnostic and set `process.exitCode = 1`; command-specific actionable diagnostics must be explicitly safe. Token command stdout is an intentional credential output, not a diagnostic or log sink.
- Do not turn staged package scripts into placeholder commands. The staged `eval` script remains unavailable until C12's real implementation/registration. Bootstrap-only empty-suite allowances must not survive introduction of real tests; current verification and acceptance status belongs in `docs/plan/PROGRESS.md`, not these reusable lessons.
- Hono 4.13.14's WebSocket declarations require web-platform `MessageEvent<T>` and `BinaryType`; Node24 standalone ambient types lack that contract. TypeScript `lib: ["ES2024", "DOM", "DOM.Iterable", "DOM.AsyncIterable"]` alongside `types: ["node"]` supplies declaration compatibility and iterable Fetch APIs, not a browser runtime requirement. `DOM.AsyncIterable` specifically declares `ReadableStream[Symbol.asyncIterator]` and `values()`, matching Node24's runtime support for `for await` over Web Streams; `DOM.Iterable` alone covers synchronous iteration only. Use these platform declarations rather than rewriting stream consumers, adding ambient shims or enabling skipLibCheck.
- Protocol parsing is not protection: an explicit allow-only stage belongs only on disposable mock traffic and must be replaced by the actual gate before real agent ingress. Adapt only supported generation endpoints/formats; missing or unsupported generation MIME must fail closed, not open a relay-controlled bypass. Manual upstream fetch redirects do not prevent downstream SDK follow: reject untrusted enforce-generation 3xx before non-ok passthrough, cancel its body, and omit Location/raw relay context; preserve explicit shadow/trusted-classifier/non-generation transport boundaries. Forward original bounded request bytes, never extracted metadata. Malformed/incomplete execution is never approval-eligible. Local/inert fixtures and mock cache fields do not prove real agent behavior or live cache hits; current status and evidence belong in `docs/plan/PROGRESS.md`.
- SSE semantic parsing does not authorize reserialization: retain original raw frames including comments, CRLF, id/retry, unknown events and multiline data, emitting them unchanged unless intentionally rewriting. Pure/early text/thinking and ping do not wait for tool decisions; C08's ordered suffix after the first withheld execution is the documented exception for later stateful content. Response hard bounds and idle/completion/decision deadlines apply independently of inbound body limits; overflow, incomplete EOF, timeout and cancellation must not release unreleased execution.
- Validate Anthropic `message_start.message.content` against the supported empty-content streaming shape before forwarding: initial execution snapshots must not bypass tracked tool withholding or approval. Aggregate response accounting must include retained serialized UTF-8 initial tool input as well as raw frames and streamed parameters. Regressions must cover zero-execution/no-approval snapshots and raw-below-cap/aggregate-over-cap initial inputs; reproduce failures before production patches.
- Codex0.164 apply_patch Update grammar permits implicit first hunks, raw blank context lines and additional chunks after a per-chunk EOF marker; use the pinned upstream streaming parser as compatibility authority rather than inventing a stricter grammar.
- Git status/diff/log/show/grep are not inherently helper-free reads (fsmonitor, filters, textconv, pager, recursive secrets). Current deterministic Git exemption is only the documented exact metadata rev-parse subset; other Git actions require review. Shared policy customization goes through resolvePolicy/EffectivePolicy once, preserving structural fail-closed invariants.
- Redact whole configured credentials against complete source content before any audit truncation; a pretruncated excerpt can retain an almost-complete credential that whole-literal replacement cannot recognize. A reviewer's own-stage credentials are not the complete configured-secret set: the real factory must pass all configured credentials and the resolved effective policy before reviewer reason truncation, retaining the1024-character output bound. C09 actual BEFORE proof observed cross-provider all-but-one-character leakage through verdict/cache/audit/tail/native/rewrite sinks; later complete-set redaction cannot repair lost source bytes. Omit an unsafe pretruncated excerpt when complete source cannot establish its safety, including when re-sanitizing historical audit-tail records; never re-emit the partial excerpt. Preserve full-source digest, truncation flags and fail-closed verdict evidence without mutating the normalized action.
- C08 actual mixed-content probes showed that withholding tool0 while immediately forwarding later text1 reverses proxy wire/history order. In Anthropic enforce, the first withheld execution must become a one-way barrier for all later content/stateful lifecycle and terminal events in one bounded ordered suffix; preserve indices and replace blocked tools in situ. Pure/early content and control-only ping/error remain immediate; do not globally buffer pure-text responses or repair request history to hide reversal.
- Correct proxy wire order does not prove client replay compatibility. In actual Claude Code2.1.311 mixed probes, repaired native tool0/text1 wire order was correct but immediate client replay reversed all three cases, and the third probe's errored result omitted the captured proxy reason; strict native acceptance remained failed. Rewrite passed all three strict mixed cases. Preserve exact per-ID wire/replay/reason evidence and original assertions; do not infer native support, specific escalation, automatic fallback or generic SDK compatibility from aggregate denied counts.
- Nonstream resource accounting must reserve raw bytes, decoded JSON/string data, parsed structures, retained output and rewrite/serialization temporaries in one aggregate ledger before allocation. Retained reasoning representations also share the separate4MiB subset, not merely the8MiB total: C08 actual before/after observed about1.5MiB thinking across three representations exceed4MiB, then reject before any decision/execution after correction. A raw-body cap alone is insufficient.
- Private GUI QA read-only bind mounts retain `/tmp`'s `nosuid` policy. Restore vendor SUID behavior only through a validated private read-only bind while retaining the vendor sandbox and host mount policy; never disable the sandbox or alter host policy to make a fixture launch. Provisioning, safety review and a corrected mount are not successful actual Desktop/CDP/agent acceptance; record real launch results separately.
- Private terminal QA must not advertise unsupported keyboard protocols: C08 actual trace queried Kitty then pushed flags5; false capability advertisement and passing private keyboard controls through pyte corrupted interpretation. Consume unsupported private controls without claiming support, interpret Enter against the actually negotiated flags, and retain protocol traces. A corrected controller/static SAFE review is not proof of why a prior UI stalled or of successful agent acceptance.
- For private GUI authentication staging, create the app-writable cookie destination only after verifying permanent UID drop. Creating it as root before dropping privileges can expose a symlink-based root-write path. C08 private staging was fixed and independently reviewed SAFE; this is a reusable privilege-ordering lesson, not a claim that exploitation occurred. Keep vendor debug/network-switch refusal separate from sandbox failure and use permitted native X11 observation rather than forcing rejected switches.
- Gray-area review has three distinct states: absent reviewer preserves gray block; a configured but unavailable reviewer follows the explicit failure policy; invalid or ambiguous reviewer JSON is an explicit block independent of failure allow. Cache only complete valid reviews, and do not replay historical stage charges on cache hits. Audit per-stage nullable unknown usage/cost rather than presenting missing data as free.
- Responses tool normalization must preserve the original audit-visible tool name and separate native namespace. Do not invent dotted tool-name aliases from namespace wrappers. `write_stdin` cannot become an ordinary command approval without trusted session association, and custom `apply_patch` must retain full patch parsing. Do not globally strip arbitrary namespaces or interpret opaque JavaScript/session continuations as shell text.
- Installed-client replay proof needs the original request, captured response item/terminal snapshots, and immediately next original request for each unique marker. Correct proxy wire order or a manually assembled HTTP history is not client proof. Bind exact denial text and ordered adjacent marker to that response; later requests, a different reason, missing capture or any unapproved execution snapshot must fail, not be repaired by rewriting history. Separately authorized harmless positive controls require their own exact execution/result correlation and budget.
- Private installed-client fixtures need fresh broker-only relay authentication and per-original-request correlation before a relay can consume a scene. Commit immutable arrival identity/order and raw URL before any body-reading await, not at body completion; keep overlap ambiguous through both owned response and capture completion. Use the core's `new URL(request.url).pathname` for canonical admission, not a framework-decoded path, and exercise encoded aliases through the actual framework fetch path. Replay evidence must preserve the entire immediate request's typed item/part sequence, not filter non-assistant items or concatenate messages to find a later matching marker. Observation may project only source-proven native metadata serialization changes, never repair captured/forwarded history.
- Preflight JSON retention from decoded keys and values, including escaped property names and the last duplicate-key value that JSON.parse actually retains. Bound scanning/allocation before parsing; a raw substring scan is not decoded semantic accounting and a discarded earlier duplicate is not the retained value.
- Use one live budget for retained protocol state, incremental SSE parser storage, decoded/parsed JSON, pending output and shadow observation, including shared Anthropic callers. Reserve before allocation and release only when the corresponding representation dies; observing consumed chunks avoids a second whole-response shadow concatenation. Match serialization units: known strings need exact UTF-16 JSON code-unit and UTF-8 wire lengths, not a pessimistic sixfold estimate that rejects valid near-limit input. Allocation-order instrumentation is not peak-heap measurement.
- Treat SSE event names as header data: validate untrusted JSON type/event values for CR/LF before any rewrite or sequence-renumber path synthesizes an event header. Reuse the shared encoder guard and fail closed; otherwise a rewritten unknown event can inject a client-visible execution frame without a decision callback. Preserve original bytes when no transformation is needed, but never bypass validation at a newly encoded header boundary.
- Distinguish semantic response changes from sequence-number changes. If a terminal snapshot's output was rewritten, never fall back to its original raw frame merely because the source sequence is already monotonic or absent; otherwise denied execution can reappear in terminal history. Preserve raw bytes only when both semantic content and outgoing framing permit it.
- Bind reasoning classification to validated item identity across the full lifecycle and parsed terminal snapshots; unknown vendor item types must not overwrite a known reasoning association. When adopting an already charged retention lease, initialize observation counters from that lease rather than zero so bounded shadow decoding still reaches its hypothetical decision and audit without changing client bytes.
- A per-child timeout is not a whole-run bound. Own setup, every mode, evidence I/O and teardown under one irrevocable deadline; initiate request aborts, reader cancellation, child stop and listener/socket shutdown before bounded joins. Register late startup ownership even after expiry, forbid subsequent launches, and treat unconfirmed cleanup as failure. A failed-cleanup process exit bounds the command, not a claim that an OS-unkillable child was reaped.
- Codex model-catalog tool_mode and multi-agent metadata can outrank fallback feature booleans. Disabling code_mode alone does not force direct shell tools for a CodeModeOnly model; custom exec consumes JavaScript and must never be aliased to exec_command. Choose a provider-supported direct catalog profile explicitly when direct tools are required, and treat a catalog candidate as static evidence until actual captured declarations establish runtime availability; a local-mock selection is not real-model/provider support.
- A fresh user Responses Message gets a UUIDv7 ID once at the accepted-input history boundary and preserves it afterward; deterministic developer msg_/at_ prefix IDs use thread/payload UUIDv5. The internal UserMessageItem ID is a different identifier, not the Responses wire ID. Independently bind expected new-user identity to native task/context/turn metadata and UserMessage corroboration before model output, then compare the complete wire ID, typed content and item count. Role=user/text alone cannot prove input origin because relay response items are also persisted; never learn expectations from the candidate tail or drop/regenerate IDs.
- Reuse JSON validation facts only for the INDIVIDUAL SSE frame whose exact bytes were checked. Aggregate incoming-chunk facts may reserve retention bytes but must never authorize a yielded frame's completeness/type/reasoning interpretation. Removing a redundant scan is safe only when the same per-frame validation and full input preflight remain authoritative.
- Keep scanner feed, snapshot and finish responsibilities separate: incremental nonstream snapshots are still required BEFORE consolidation/decoding/parsing allocations to reserve pending reasoning correctly. Cache a finalized status and make finish/cleanup idempotent so normal/failure finally paths do not rescan or release twice. Evaluate performance fixes with unchanged workloads, guards, warmups, samples and thresholds; a diagnostic CPU/GC profile alone does not prove an exclusive cause.
- A clean subprocess PATH may omit a legitimately installed NVM interpreter. Resolve and validate the approved absolute executable path statically before a budgeted launch; do not mislabel a pre-broker FileNotFoundError as a vendor/client failure or silently change global PATH/profile settings.
- Classify a vendor sandbox failure from the actual startup error plus read-only kernel/policy evidence, not auth/Linux/gateway guesses. If the approved private environment has no compliant remedy without forbidden policy/sandbox changes, retain a concrete external safe-host prerequisite—never use --no-sandbox or install host policy merely to green QA. A stale owned-PID registry is not a live verdict; qualify only recorded targets via metadata, and do not STOP/kill when their process/cgroup records are absent.
- WorkBuddy route project_dirs is trusted project scope, not a client-home oracle. Existing trusted ActionContext home_dir/userprofile can resolve home spellings; absent that context, leave %USERPROFILE%/tilde unresolved for conservative policy review. Never substitute the gateway host environment or derive a remote home from a project's apparent username. C06 already owns Windows lexical rules and explicit-other visible-capability checks; do not introduce a second convention during Chat integration.
- Chat Completions has a different release contract from Anthropic/Responses: emit safe content/reasoning immediately, splitting mixed chunks once, while retaining execution and terminal finish/usage/[DONE] through whole-turn validation and decisions. Do not import an ordered-suffix barrier or globally buffer text just because another adapter needs it. Mock scenes/setup snippets cannot establish WorkBuddy approval mode, auxiliary-header presence/absence or actual-client replay.
- Official homepage-linked manifests identify product/platform URLs, not retrievable or verified packages: preserve the exact primary-source chain, package family, version/channel uncertainty and empty publisher hashes, then distinguish metadata retrieval from acquisition/install/runtime evidence. Keep permission/product scopes exact too: model Auto Mode, Default Permissions, a sibling CLI's auto approval, Enterprise or online UI cannot establish the requested desktop intelligent-approval mode. A bounded failed artifact lookup is not unsupported-Linux, authentication or another app's sandbox evidence.
- An explicitly configured tool_map.arg is authoritative, not a preferred hint: missing/wrong/blank command or URL selection must not fall through to another conventional field. File-write content has different semantics: missing/non-string selected content is unavailable, but an empty string is a valid empty-file write. Preserve conventional fallback only when arg is unconfigured and keep visible-capability/explicit-other checks intact.
- Tool declaration descriptions must reach the actual normalizer, not just adapter extraction or unit fixtures. Pass extracted RequestContext only into normalization's ActionContext when needed for capability detection; keep full tools/messages/model instructions out of the curated GateContext/provider state. A description-hinted execution with unassessable arguments must structurally block, while genuine generic-other retains its locked policy.
- Chat non-null usage is authoritative terminal accounting regardless of chunk shape; usage:null is only a placeholder, not the first authoritative usage. Split safe content/reasoning immediately, retain the single non-null usage through finish/EOF/decisions, and reject duplicate authoritative usage promptly even if upstream stays open.
- Capture bounded SSE event/id metadata before releasing semantic parser storage when a frame may be rewritten later. Deferred rewriting must own that charged metadata and pass it through the guarded encoder; getters backed by released semantic storage cannot preserve original header semantics.
- Releasing a budget reservation does not drop its referenced bytes. Remove processed queue/frame/raw references before returning their credit or transferring it to generated output; otherwise serialization can reuse credit while original buffers remain reachable. A release-order trace plus source reachability analysis is not a measured live-heap peak.
